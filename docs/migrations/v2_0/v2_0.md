# Migrating to v2.0

v2.0 verifies the agent's answer itself. In v1, the agent returned a structured `SourceryKitAgentResponse` with `claimed_values`, and you built and evaluated a handoff payload from them. In v2, the agent answers in plain text: you run it inside `run()` and pass its answer to `verify`, which checks every statement against the recorded calls and proves every value it relies on. Claims no longer come from the agent's output format, so an agent needs no special schema, and a value the agent states without claiming it is no longer missed.

## Breaking changes

### Removed from the public API

| v1 | v2 |
|---|---|
| `SourceryKitAgentResponse`, `ClaimedValue` | Nothing: the agent answers in plain text. Remove `output_type=` / `response_format=` / `output_format=`. |
| `build_handoff_payload`, `evaluate_handoff`, `HandoffPayload`, `VerificationMode` | `async with run() as r:` around the agent, then `report = await r.verify(answer, model=...)`. |
| `sourcerykit_ref` returned by tools | Nothing: `async_intercept_context` yields nothing, and tools return the plain response. Verification tells the calls apart by URL and content. |
| `evaluate_handoff(...)["outcome"]`, `["per_claim"]` | `report.outcome`, `report.claims`; `print(report)` shows both. |
| `start_mock_server` (`sourcerykit.testing`) | Serve your test data from a small local server; the multi-agent cookbooks show one in about 15 lines. |
| `sourcerykit trace list`, `trace show` and the trace dashboard | `print(report)`; the report holds every claim, verdict and proof. |
| `SOURCERYKIT_TABLE_ID`, `SOURCERYKIT_COLLECTION_ID`, `SOURCERYKIT_INTEGRATION_KEY` | `SOURCERYKIT_FACTS_TABLE_ID`, `SOURCERYKIT_FACTS_COLLECTION_ID` (set by `sourcerykit doctor --fix` or `init`). |

### A new outcome: `PASS_WITH_NOTES`

`PASS_WITH_NOTES` means nothing is contradicted, but some statements have no data to check them; the report lists them as not verifiable. Code that tests `outcome == "PASS"` treats it as not passing; decide whether your flow accepts it. `CAUGHT` now means a statement is contradicted by the recorded data, and `ERROR` that nothing could be checked.

### Trusted endpoints no longer block requests

In v1, recording a call to an endpoint missing from the trusted list raised `SourceryKitTrustError`, and the list was required. In v2 the list is optional and nothing is blocked: with no list, every recorded call is evidence; with one, calls to other endpoints are recorded but left out of verification and listed in the report as untrusted. If you relied on the block to stop requests, enforce it in your tools. See [trusted endpoints](https://sourcerykit.provably.ai/docs/pillars/trusted-endpoints).

### Verification needs a linker model

`verify` asks a model of your choice to turn the answer into checks. Set `SOURCERYKIT_LINKER_URL` and `SOURCERYKIT_LINKER_API_KEY`: `https://api.anthropic.com` for Claude's Messages API (`pip install "sourcerykit[anthropic]"`), or the base URL of an OpenAI-compatible chat API, such as `https://openrouter.ai/api/v1`. See [the linker](https://sourcerykit.provably.ai/docs/getting_started/onboarding#the-linker).

## Porting an agent

The [OpenAI Agents SDK cookbook](https://sourcerykit.provably.ai/docs/cookbooks/openai_agents), before and after:

```python
# v1
@function_tool
async def get_current_temperature_london() -> dict:
    async with async_intercept_context(agent_id="demo", action_name="get_weather") as ref:
        async with httpx.AsyncClient() as client:
            response = await client.get(URL, params=PARAMS)
    return {**response.json(), "sourcerykit_ref": ref}

await insert_trusted_endpoint(url=URL)
agent = Agent(name="weather-demo", instructions=..., tools=[...], output_type=SourceryKitAgentResponse)
result = await Runner.run(agent, prompt)
payload = await build_handoff_payload(
    {"answer": result.final_output.answer,
     "claims": [{"action_name": "get_weather", "claimed_value": result.final_output.claimed_values,
                 "verification_mode": "field_extraction"}]},
    run_id=uuid.uuid4(), prompt=prompt, intercept_agent_id="demo",
)
eval_result = await evaluate_handoff(payload=payload)
print(eval_result["outcome"])
```

```python
# v2
@function_tool
async def get_current_temperature_london() -> dict:
    async with async_intercept_context(agent_id="demo", action_name="get_weather"):
        async with httpx.AsyncClient() as client:
            response = await client.get(URL, params=PARAMS)
    return response.json()

agent = Agent(name="weather-demo", instructions=..., tools=[...])
async with run() as weather_run:
    result = await Runner.run(agent, prompt)
report = await weather_run.verify(result.final_output, model="anthropic/claude-haiku-5.5")
print(report)                  # report.outcome: PASS, PASS_WITH_NOTES, CAUGHT or ERROR
problems = await check(report)  # [] when every proof, claim and verdict holds
```

Multi-agent pipelines need one `run()` around the whole pipeline, and `verify` on the final answer. Every cookbook has been ported: mirror the one closest to your framework.

## Schema change

Migration `006` adds the `facts` table, which holds the responses of the run being verified, sealed by the QEDB middleware. With your own PostgreSQL, `bootstrap_system()` and `sourcerykit upgrade` create it; hosted sandboxes get it from Provably. The `traces` and `trace_intercepts` tables are no longer used, and are left in place with their data.

## Upgrade

```bash
pip install --upgrade sourcerykit
sourcerykit upgrade        # applies migration 006 to your own PostgreSQL
sourcerykit doctor --fix   # finds the facts table in Provably and saves its ids to .env
```

Provably learns your database's tables when it scans it, which it last did when you connected it. If `doctor --fix` or `bootstrap_system()` then reports `Table 'facts' not found`, open your database in the Provably web app and save it unchanged: saving rescans it. Hosted sandboxes need nothing.

Then set the linker variables above, remove `SOURCERYKIT_TABLE_ID`, `SOURCERYKIT_COLLECTION_ID` and `SOURCERYKIT_INTEGRATION_KEY` from your `.env`, and port your agent as shown. `sourcerykit doctor` should report 5 checks passed.
